# 前后端 / 客户端 / 数据库的关系

## 餐厅类比

```
顾客（用户）→ 服务员（前端/客户端）→ 厨房（后端）→ 冰箱/仓库（数据库）
```

---

## 各层职责

### 前端/客户端 = 服务员 + 菜单 + 餐厅装修

用户能看到、能摸到的一切。网页、App 界面、按钮、动画。它的职责：
- 把信息漂亮地展示给用户
- 收集用户的操作（点了什么、输了什么）
- 把请求传给后端

### 后端 = 厨房

用户看不到，但干真正的活。它的职责：
- 处理业务逻辑（下单、扣款、验证身份）
- 决定该给前端返回什么数据
- 跟数据库打交道（存取数据）
- 调用外部服务（支付、短信）

### 数据库 = 仓库/冰箱

只负责**存东西和取东西**。用户信息、订单记录、文章内容，全在这里。它不思考，只听后端的指令：存这条、取那条、删掉这个。

---

## 配合流程（以「用户登录」为例）

```
1. 用户在前端输入账号密码，点登录
2. 前端把账号密码发给后端
3. 后端拿着账号去数据库查：这人存在吗？密码对吗？
4. 数据库返回查询结果给后端
5. 后端判断结果，告诉前端：「成功」或「密码错误」
6. 前端根据结果显示：跳转首页 或 弹出错误提示
```

---

## 前端 vs 客户端

基本是一回事，只是场景不同：
- 网页端叫**前端**（浏览器里跑的）
- 手机端叫**客户端**（App）
- 本质都是「用户直接交互的那一层」

---

## 一句话总结

**前端负责「好看」，后端负责「好用」，数据库负责「记住」。**

---

## Mock 数据与联调

### Mock 数据

前端开发时用的模拟数据，模拟后端接口返回，让前端不用等后端写完就能把页面逻辑跑通。

Mock 的本质是：**在真实接口还没好的时候，让前端不被阻塞，实现并行开发。**

后端也会 mock 外部依赖（如第三方支付接口、短信服务）来测试自己的逻辑。

**谁依赖了不受自己控制的东西，谁就需要 mock。**

### 联调

前后端真实对接，用真实接口、真实数据库。验证两边对接口的理解是否一致：
- 字段名对不对
- 数据格式对不对
- 错误码处理对不对
- 鉴权流程通不通

### 开发流程

1. 先约定好接口文档（字段、格式、状态码）
2. 前端按文档写 mock，自己跑通页面逻辑
3. 后端按文档实现真实接口
4. 两边都写完了，联调 — 验证双方对文档的理解一致

**每完成一个模块就联调一次，不要攒到最后。** 问题当场暴露当场修。

### 联调主要改哪边

两边都可能改，但大多数情况下**前端改得多**。

原因：后端以接口文档为准，只要返回的数据符合文档就算对了。前端是消费方，要适配后端实际返回的数据结构。

常见前端要改的：
- 字段名对不上（前端写了 `data.list`，后端返回的是 `data.items`）
- 数据类型不对（以为是数组，实际是对象）
- 缺少 loading / 错误状态处理
- 分页参数格式不一致

后端要改的情况：
- 接口文档设计不合理，前端用起来别扭
- 缺少某个前端需要的字段
- 返回的数据需要额外处理（比如前端需要的排序后端没做）

如果接口文档一开始就定得清楚、双方严格按文档开发，联调时两边都不用大改。

### 联调怎么做

联调只需要一次，不需要前后端分别各调一遍。流程：

1. 把后端跑起来（`node server.js` 或类似命令）
2. 把前端跑起来（`npm run dev`）
3. 前端页面上操作，看请求有没有正确发到后端、后端返回的数据前端能不能正确展示
4. 哪边有问题改哪边

联调本身就是**两边同时跑着，对着测**。一个窗口统一做就行。

## 启服务、端口、kill 端口

### 启服务 = 让程序开始营业

你写的代码只是一堆文件，躺在硬盘上什么都不干。`node server.js` 就是让它「跑起来」，变成一个活的程序，随时准备接收和处理请求。这就叫启动服务。

### 端口 = 门牌号

你的电脑 IP 地址相当于一栋大楼的地址。但大楼里有很多房间，端口就是房间号。

- `localhost:3000` → 这栋楼（你电脑）的 3000 号房间
- `localhost:5173` → 5173 号房间

一共有 65535 个房间可以用。前端服务占一个房间，后端服务占另一个房间，互不冲突。

比如：
- 前端跑在 `5173` 端口
- 后端跑在 `3000` 端口
- 数据库跑在 `5432` 端口

### 为什么要 kill 端口

一个端口同一时间只能被一个程序占用。就像一个房间只能开一家店。

如果你上次跑的服务没正常关掉（比如直接关了终端而不是 Ctrl+C），那个程序还在后台占着端口。你再启动一次，就会报错：

```
Error: port 3000 is already in use
```

意思是「3000 号房间已经有人了，进不去」。

kill 端口 = 把占着房间的那个程序强制赶走，腾出位置让新的服务进去。

```bash
# 找出谁占了 3000 端口
lsof -i :3000

# 杀掉那个进程
kill -9 <进程ID>
```

### 一句话总结

**启服务 = 让代码跑起来等请求。端口 = 房间号，每个服务各占一间。kill 端口 = 上一个房客没走，把它赶走。**
